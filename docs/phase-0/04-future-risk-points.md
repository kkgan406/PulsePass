# 未来风险点

以下仅记录基础流程中的风险，不设计或实现解决方案。

| 问题 | 如何发生 | 基础实现为何无法天然避免 |
| --- | --- | --- |
| 库存超卖 | 多个请求同时看到剩余库存并各自购买，最终售出数量可能超过库存。 | 查询、检查和扣减分离，并发请求可同时通过检查。 |
| 同一用户重复订单 | 同一用户对同一活动的并发购买都查询到没有有效订单，各自创建订单，即使选择了不同票种。 | 查询已有订单与创建订单之间存在时间窗口。 |
| Inventory 并发读写 | 多个请求基于同一旧库存值计算并写回，后写入覆盖先前变化。 | 普通读、修改、写操作无法天然隔离相互交错的执行。 |
| 库存扣减成功但订单创建失败 | 库存写入后，订单创建操作失败。 | 基础流程未保证两个步骤作为一个整体成功或失败。 |
| 重复请求 | 客户端超时后重试，或请求被重复提交，可能再次执行购买。 | 基础流程没有定义如何识别同一次请求；购买检查也可能并发通过。 |
| 服务异常导致中间状态 | 服务在库存扣减后、订单创建前中断，或响应前中断。 | 中间步骤可能已生效，而后续步骤或响应尚未完成，调用方无法仅凭超时判断结果。 |
